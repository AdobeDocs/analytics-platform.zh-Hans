# 数据馈送中的分段

{{release-limited-testing}}

Customer Journey Analytics中的数据馈送支持分段，以便您过滤每个馈送交付中包含的行。 您可以在数据视图级别、馈送级别应用区段，或同时应用两者。

## 应用区段的地方

您可以将区段应用到数据馈送中的两个位置：

- **数据视图**：在数据视图中配置的区段，适用于使用该数据视图的所有馈送。
- **数据馈送**：除了任何数据视图区段之外，还直接应用于单个馈送的区段。

配置这两个区段后，Customer Journey Analytics会将其合并 — 只有满足这两个区段的行才会包含在信息源输出中。

## 日期范围区段

数据馈送支持引用日期范围的区段。 但是，该行为与Analysis Workspace有很大区别：**区段中的日期范围条件不会覆盖馈送的报表日期范围。**

在Analysis Workspace中，应用日期范围区段会更改活动报表窗口以匹配区段的日期范围。 在数据馈送中，报表窗口始终由馈送的计划提交（每小时或每天）定义。 具有日期范围条件的区段会过滤该窗口中的行 — 它不会移动或展开窗口本身。

这种设计是有意为之。 允许日期范围区段覆盖报告窗口可能会导致每小时的馈送提供比预期大得多的数据窗口，从而导致数据重复或输出量过大。

### 示例

**示例1 — 包含特定日期事件的区段**

假设您应用一个仅返回7月1日事件的区段，并运行7月22日的信息源：

- 馈送交付窗口仍为7月22日。
- 区段会过滤掉所有行，因为7月22日窗口内的事件均不符合7月1日标准。 馈送将运行，但不提供行。
- 如果您在7月1日运行回填，则该区段会按预期运行 — 仅包含符合7月1日条件的事件。

**示例2 — 从特定日期排除事件的区段**

假设您应用了一个区段，该区段排除了7月1日订购的所有事件，并在7月22日运行信息源：

- 该区段适用于7月22日的数据。 由于7月22日窗口中没有任何7月1日事件，因此不会排除任何事件，并且所有行都会交付。
- 如果您在7月1日运行回填，则该区段会按预期排除相关行。

## 包含多个条件的区段

对于将日期范围条件与其他标准相结合的区段，Customer Journey Analytics仅将日期范围部分作为行过滤器进行评估，而不会作为报表窗口覆盖进行评估。 区段中的所有条件都将在馈送的投放窗口中接受。

## 区段鉴别和回顾日期范围

对于使用人员或会话容器的区段，资格由&#x200B;**回顾日期范围**&#x200B;设置决定，而不只是投放时间范围决定。 如果人员在回顾日期范围内符合条件，则包含该人员在投放窗口中的所有事件。 容器设置确定范围：

- **事件容器**：仅包含与投放窗口中的区段条件匹配的事件。
- **会话容器**：包括投放窗口内符合条件的会话中的所有事件，其中会话资格将在回看日期范围内进行评估。
- **人员容器**：对于在回顾日期范围内符合条件的任何人员，将包含投放窗口内的所有事件。

有关回顾日期范围及其对区段鉴别的影响的详细信息，请参阅[创建数据馈送](/help/components/exports/cja-data-feeds/create-feed.md)。

## 与Analysis Workspace比较

| 行为 | Analysis Workspace | 数据馈送 |
|---|---|---|
| 日期范围区段覆盖报告时段 | 是 | 否 |
| 区段过滤报告窗口中的行 | 是 | 是 |
| 数据视图区段适用 | 是 | 是 |
| 直接应用于投放的其他区段 | 否 | 是 |
